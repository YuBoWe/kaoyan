# 第二章 进程与线程

## 进程上下文切换 vs 内存对换（Swapping）

**上下文切换只动“寄存器和管理信息”，不动“本体”：** 当一个进程被换下 CPU 时，它的代码和数据依然**完好地保存在主存（内存）中**。操作系统只需要把当前 CPU 里的各种寄存器值（如程序计数器 PC、堆栈指针 SP 等）保存到该进程的 **PCB（进程控制块）** 中即可（PCB 同样在内存中）。

**移到磁盘那是“对换（Swapping）”：** 把整个进程的代码和数据从内存中剥离并写入磁盘的交换区（Swap），这是内存管理中的**中级调度（对换机制）**，只有在内存严重不足时才会触发，开销极大，绝不是常规上下文切换会做的事。



进程上下文指进程的代码、数据以及支持进程执行的所有运行环境

进程上下文切换机制实现了不同进程在一个处理器中交替运行的功能

进程上下文切换过程中必须保存换下进程在切换处的程序计数器（PC）的值



###  软件实现方法

- **单标志法**：违背了“空闲让进”（因为必须轮流进入，临界区空闲时可能也进不去）。
- **双标志先检查法**：违背了“忙则等待”（可能同时进入临界区）。
- **双标志后检查法**：可能导致双方都进不去，产生死锁。
- **Peterson 算法**：虽然完美满足了“空闲让进”、“忙则等待”和“有限等待”，但当进程进不去临界区时，代码会执行： `while(flag[j] && turn == j);` 这是一个死循环，进程卡在 CPU 里疯狂试探，**严重违背了“让权等待”**。

### 硬件实现方法

- **关中断**：不属于忙等，但直接把中断关了，权力太大，甚至违背了多道程序设计的初衷（代价太大）。
- **TSL 指令 (TestAndSet) / Swap 指令 (XCHG)**： 它们利用硬件原子操作来加锁，但写成代码通常是： `while(TestAndSet(&lock));` 只要别人拿着锁，当前进程就会卡在 `while` 循环里疯狂消耗 CPU 时钟周期。这种锁在工程上被称为**自旋锁（Spinlock）**，同样**严重违背了“让权等待”**。



# 第三章 内存管理

## 绝对装入和可重定位装入和动态运行时装入

| **特性**             | **绝对装入 (Absolute)** | **静态重定位装入 (Static)** | **动态运行时装入 (Dynamic)** |
| -------------------- | ----------------------- | --------------------------- | ---------------------------- |
| **地址转换时机**     | **编译或汇编时**        | **程序装入内存时**          | **执行到该指令时（运行时）** |

| **环境支持**         | 单道程序系统            | 早期多道程序系统            | 现代虚拟内存操作系统         |



### 虚拟内存的概念和边界

概念：

**“你独占整个天下的内存”**：每个进程都有一个自己独立的虚拟地址空间。在 32 位系统下，每个进程都以为自己拥有连续、平滑的 $4\text{ GB}$ 内存，它觉得自己是一个高高在上的国王，不需要跟任何其他进程共享空间。

**“你看到的地址都是真的”**：C 语言里 `malloc()` 返回的指针、代码里跳转的地址，全都是在这个虚构空间里的**虚拟地址（逻辑地址）**。

**按需付薪（请求调页）**：进程以为自己有 $4\text{ GB}$，但操作系统根本没给它分配那么多物理内存。只有当进程真正去读写某块代码或数据，发现“哎呀，内存里没有”并触发**缺页异常**时，操作系统才会急匆匆地从硬盘把数据读进物理内存，并偷偷修改页表。



**边界之一：容量边界**

理论边界（最大容量）

虚拟内存的**最大容量**，完全由 **CPU 的寻址位数（地址总线宽度）** 决定。

这是由硬件死死卡住的。因为指针的长度是固定的，如果 CPU 只有 32 位，那么它发出的地址最多只能有 32 个二进制位。

$$\text{最大容量} = 2^{n} \text{ 字节} \quad (n \text{ 为地址位数})$$

- 如果地址位数为 32 位，最大容量就是 $2^{32}\text{ B} = 4\text{ GB}$。
- **边界铁律**：无论你的物理内存加到多大（比如 $64\text{ GB}$），或者硬盘有多大（比如 $4\text{ TB}$），在 32 位系统下，一个进程的虚拟地址空间**死活都不可能超过 $4\text{ GB}$**。因为超过 $4\text{ GB}$ 的地方，CPU 的指针根本指不过去！

实际边界（实际最高上限）

在实际运行中，虚拟内存也不可能无限画大饼，它还会受到物理硬件总和的约束。

$$\text{实际容量} = \min(\text{物理内存容量} + \text{外存对换区容量}, 2^{n})$$

- **边界铁律**：如果你的物理内存是 $8\text{ GB}$，硬盘对换区（Swap）分了 $16\text{ GB}$，那么哪怕在 64 位系统下（理论寻址空间极大），你实际能撑起的虚拟内存总和最大也就是 $8 + 16 = 24\text{ GB}$。再多的话，硬盘和内存都装不下了，大饼就彻底画塌了。



**边界之二：权限与隔离边界**

虚拟内存除了管理容量，另一个宏观使命是**筑墙**。它划定了两条安全的边界：

- **进程边界（横向隔离）**：每个进程都有自己专属的页表。进程 A 的虚拟地址 `0x00400000` 映射到物理内存的块 10；进程 B 的虚拟地址 `0x00400000` 映射到物理内存的块 20。进程 A 就算想破脑袋，也绝不可能通过自己的指针去修改进程 B 的数据。
- **访问权限边界（纵向隔离）**：这就是页表项里的“保护位”。操作系统在把虚拟内存划分成各个区域时，就立下了规矩：
  - 代码段（Text）的虚拟地址空间：只允许“读取”和“执行”，不允许“写入”。如果你写代码尝试去修改正在运行的机器指令，MMU（内存管理单元）硬件就会立刻报错，弹出一个大大的 `Segmentation fault`（段错误）。
  - **数据段/堆栈段**：允许“读取”和“写入”，但默认不允许“执行”（防止黑客注入恶意代码并执行）。



### 缺页异常生命周期

1. 触发阶段（硬件 MMU）

- **触发条件**：CPU 访存 $\rightarrow$ 查页表 $\rightarrow$ **存在位（有效位）= 0**。
- **中断性质**：**内中断（异常 / 故障 Fault）**。由 CPU 内部执行指令引起。

2. 接管阶段（CPU 到 OS）

- **现场保护**：CPU 自动保存通用寄存器和 PC。
- **状态切换**：从**用户态 $\rightarrow$ 核心态**，跳转到操作系统的缺页中断处理程序。

3. 处理阶段（OS 核心，高频考点）

- **分配物理页框**：
  - **有空闲**：直接使用。
  - **无空闲**：运行页面置换算法淘汰一页。**若淘汰页的修改位（脏位）= 1，必须先写回磁盘**。
- **磁盘 I/O 换入**：启动磁盘读命令，将外存中的目标页读入物理内存。
- **进程切换**：磁盘 I/O 极慢，当前进程变为**阻塞态**，释放 CPU，OS 调度其他进程运行。

4. 恢复阶段（闭环）

- **页表更新**：磁盘读完 $\rightarrow$ 触发**外中断**通知 CPU $\rightarrow$ OS 修改该页表项：**存在位改 1**，填入物理页框号 $\rightarrow$ 唤醒原进程（转为**就绪态**）。
- **指令复执（死考点）**：原进程重新获得 CPU $\rightarrow$ **重新执行刚才引发缺页的那条原指令**（PC 不加 4）。



### 改进型 Clock（时钟）置换算法的流程

一、 核心基础：2个指标与4种状态

每个页面用一个二元组 **(访问位 $A$, 修改位 $M$)** 来表示：

- **$A = 1$** 表示最近被访问过，**$A = 0$** 表示没被访问过。
- **$M = 1$** 表示被修改过（脏页），**$M = 0$** 表示没被修改过（干净页）。

组合起来，页面一共有 4 种状态，从最好到最坏的淘汰顺序是：

1. **(0, 0)**：最近没访问，也没修改。（**最佳淘汰对象**，直接丢弃）
2. **(0, 1)**：最近没访问，但修改过。（需要写回磁盘，次之）
3. **(1, 0)**：最近访问过，但没修改。（可能还要用，再次之）
4. **(1, 1)**：最近访问过，且修改过。（**最不该淘汰**）



二、 核心流程：4轮扫描算法（做题必背绝对步骤）

算法从当前指针位置开始，在物理页框构成的**循环队列**中按以下步骤扫描。**最多进行 4 轮扫描，一旦在中途找到目标页，立即停止并置换该页。**

第一轮：寻找 (0, 0)

- **规则**：从当前位置开始循环扫描，寻找状态为 `(0, 0)` 的页面。
- **注意**：本轮**不修改**任何页面的访问位。
- **结果**：找到就置换；没找到就进入第二轮。

第二轮：寻找 (0, 1)，同时“变 0”

- **规则**：重新从当前位置开始扫描，寻找状态为 `(0, 1)` 的页面。
- **核心考点**：在扫描过程中，**所有被指针越过的页面，其“访问位 $A$”一律清零（由 1 变成 0）**。
- **结果**：找到就置换；如果把整个队列扫完了都没找到，进入第三轮。

第三轮：再次寻找 (0, 0)

- **规则**：因为第二轮把所有页面的 $A$ 都变成了 0，此时页面状态只剩下 `(0, 0)` 和 `(0, 1)` 了。重新扫描，寻找状态为 `(0, 0)` 的页面。
- **注意**：本轮**不修改**任何标志位。
- **结果**：找到就置换；没找到就进入第四轮。

第四轮：再次寻找 (0, 1)

- **规则**：从当前位置扫描，寻找状态为 `(0, 1)` 的页面。
- **结论**：走到这一步，**必然能找到**满足条件的页面并置换。

## VFS

VFS（Virtual File System，虚拟文件系统）



**考点一：VFS 的核心存在意义（考“统一接口”）**

真题最喜欢考 VFS 的定义和为什么需要它。你只需要记住：**对上统一接口，对下屏蔽差异**。

- **怎么考**：题目可能会描述一个场景：“系统里同时挂载了 ext4、FAT32 和 NTFS 格式的盘，为什么用户可以用同一种方式（如 `read`、`write` 函数）去读写它们？”
- **标准答案**：因为有了 VFS。VFS 定义了一组通用的、抽象的系统调用接口。
- **核心结论**：**VFS 只存在于内存中，它在磁盘上没有对应的实体！**（如果选项说“VFS 会在磁盘上创建XX结构”，果断排除）。



**考点二：文件系统级联的核心结构（经典数据结构映射）**

这是 VFS 互联的核心，通常会结合进程管理、文件管理一起考。 Linux 系统的 VFS 抽象出了 4 种核心对象，真题极其喜欢考它们的分工：

1. **超级块对象 (Superblock)**：存放具体文件系统的**全局元数据**（比如这个分区总共有多大、用了多少）。
2. **索引节点对象 (Inode)**：存放**具体文件**的元数据（文件大小、权限、在磁盘的哪个块）。**注意：它和磁盘上的 inode 是一一对应的。**
3. **目录项对象 (Dentry)**：存放**目录树的结构**（文件名和 inode 的映射关系）。比如路径 `/home/user/a.txt`，每一级都是一个 dentry。它只存在于内存中，用来加速路径解析。
4. **文件对象 (File)**：代表**进程打开的一个文件**。记录了当前读写到哪了（读写指针 offset）。

> 💡 **408 必杀避坑陷阱**：
>
> - `inode` 关注的是**文件本身**（这个文件在磁盘哪里，多大）。
> - `file` 关注的是**进程的动态行为**（这个文件被谁打开了，读到第几行了）。
> - **同一个文件被打开两次，会有两个 `file` 对象，但只对应同一个 `inode`。**





**考点三：从进程到磁盘的“指针大乱斗”（超级高频考点）**

408 非常喜欢考当一个进程执行 `int fd = open("a.txt", ...)` 时，操作系统内部的指针是怎么一级一级指过去的。

这个调用链条非常固定，闭着眼睛都要能背出来：

1. **进程控制块 (PCB)** 里面有一个 **文件描述符表 (fd_array)**。
2. 我们常说的 `fd`（比如 0, 1, 2）其实就是这个表的**下标**。
3. 这个表项里的指针，指向系统全局的 **打开文件表 (Open File Table)**，这里面存的是 `file` 对象（记录了读写指针 `offset`）。
4. `file` 对象再指向 VFS 的 **v-node (或 in-memory inode)**。
5. `v-node` 最终对应到具体文件系统的 **disk inode**。

- **真题怎么挖坑？**
  - *坑点 1*：多个进程共享同一个文件，写指针（offset）会互相影响吗？
    - **答案**：如果是各自独立 `open` 的，它们在“打开文件表”里有各自的 `file` 对象，读写指针**互不影响**；如果是 `fork` 出来的子进程，它们会共享同一个 `file` 对象，读写指针**会互相影响**。
  - *坑点 2*：什么是 `v-node`？
    - **答案**：它是 VFS 的灵魂。不管底下的磁盘是 Windows 的 FAT32 还是 Linux 的 ext4，在 VFS 层一律被抽象成 `v-node`。`v-node` 里还包含了一个非常关键的东西——**函数指针表（file_operations）**，它指向了具体文件系统的驱动代码。



# 第五章 IO

## I/O管理概述

- 双缓冲技术的性能计算: 对双缓冲处理时间的公式理解稍有偏差。在双缓冲中，设备传数据到缓冲区（T）与CPU处理工作区数据（C）是可以并行工作的，因此系统处理一个数据块的期望时间应为 max(*C*,*T*)+*M*。
- I/O软件层次结构中的算法划分: 磁盘调度算法（如SCAN、CSCAN算法）需要紧密依赖磁盘的物理结构（如当前磁头所在的柱面位置）来进行优化，因此它们通常运行在具体的“设备驱动程序”层，而不是设备独立性软件层。



## 设备驱动程序

1. 初始化设备（开局配置）
2. 翻译命令（承上启下）:将操作系统高层的**通用、抽象命令**，转换成特定硬件能懂的**低层、具体命令**
3. 控制数据传输（对接 I/O 方式）: 根据硬件支持的 **I/O 控制方式**（轮询、中断、DMA 或通道），驱动程序要写不同的逻辑。比如在 DMA 方式下，驱动程序负责把内存起始地址和传输长度写给 DMA 控制器，然后启动传输。
4. 处理硬件中断（善后与唤醒）: 它会去读取设备状态寄存器，看看是“顺利完工”还是“中途出错”；如果是读数据，它负责把数据从设备缓冲区挪到内核缓冲区，最后**唤醒**那个正在苦苦等待的阻塞进程。
5. 监测与报告设备状态（状态管理）:记录设备是处于“忙碌（Busy）”还是“空闲（Idle）”；如果硬件坏了、断线了或者卡死了，驱动程序要把这些错误抽象成标准错误码，报告给操作系统内核。



## 磁盘初始化的三个步骤

**物理格式化 / 低级格式化（Low-level Formatting）**

- **谁来做**：通常由磁盘制造商在出厂前完成。

- **做什么**：将磁盘的磁性表面划分为一个个**扇区**（Sector）。每个扇区填入特殊的数据结构，包括：扇区头（包含扇区号）、数据区、扇区尾（包含**循环冗余校验码 CRC/ECC** 等）。

  

**磁盘分区（Partitioning）**

- **谁来做**：操作系统或用户（使用分区工具）。

- **做什么**：将磁盘划分成一个或多个柱面组（即我们熟悉的C盘、D盘、E盘等分区）。每个分区在逻辑上可以看作是一个独立的磁盘。

  

**逻辑格式化 / 高级格式化（Logical Formatting）**

- **谁来做**：操作系统（例如我们在Windows里右键点击盘符选择“格式化”）。

- **做什么**：在分区上**创建文件系统**（如NTFS、FAT32、ext4等）。操作系统需要在这个阶段向磁盘写入文件系统的初始数据结构。

- **具体包括**：

  - **初始化保存空闲磁盘块信息的数据结构**（例如创建位图 Bitmap、空闲块链表或FAT表，用来管理哪些空间是空的）。
  - **建立文件系统的根目录**（如 `/` 或 `C:\`），以便后续用户可以在里面创建文件和文件夹。
